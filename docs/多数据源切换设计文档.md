## 1. 背景与目标

当前 `chatbi/` 硬编码只连 `chatbi/data/olist.db`（`agent/tools/query_data.py:29`）；schema、few-shot 均按 SQLite 单库人工整理。本期扩展 ChatBI 能力：

- 支持 **SQLite / MySQL / PostgreSQL** 三种关系型数据库
- 内置 demo（olist）+ **允许用户连接自己的云上数据库**（公网开放，带 SSRF 缓解，见 §6）
- 每个会话绑定一个数据源，切换会话自动切数据源
- Schema 自动内省 + 用户可编辑业务注释
- SQL 方言按数据源类型注入 prompt（含方言差异速查表 + 方言专属 few-shot）

**非目标**：NoSQL / OLAP / 视图与存储过程展示 / schema 变更自动检测 / 数据源共享 (RBAC)。

## 2. 架构

```
前端
  DataSourceManager (抽屉/弹窗)
    ├─ 列表：内置 demo (olist) + 用户自建
    ├─ 新建：type / host / port / user / password / db
    ├─ 测试连接 → 内省 schema → 可编辑注释表
    └─ 会话与 datasource 绑定 (创建会话时选择，会话内不可换)

FastAPI
  routers/datasources.py       ← CRUD + test + introspect + refresh
  services/datasource_store.py ← SQLite 存取 (Fernet 加密密码；复用功能一的存储封装)
  services/ssrf_guard.py       ← 内网黑名单 + 端口白名单（新增，见 §6）
  services/introspect.py       ← SQLAlchemy inspect() 抓 schema
  services/sql_executor.py     ← 统一执行层 (SQLAlchemy Core；engine 缓存见 §5)
  chatbi/dialect.py            ← 方言判定 + 差异速查表
  chatbi/few_shots/            ← sqlite.py / mysql.py / postgresql.py
  chatbi/schema_render.py      ← JSON schema → prompt markdown

data/sessions.db  (新增 data_sources 表 + sessions.datasource_id，启动迁移见 §10)
```

## 3. 数据模型（追加到 `data/sessions.db`）

```sql
CREATE TABLE data_sources (
  id            TEXT PRIMARY KEY,
  user_id       TEXT NOT NULL,          -- 内置 demo 时为 '__builtin__'
  name          TEXT NOT NULL,
  type          TEXT NOT NULL,          -- 'sqlite' | 'mysql' | 'postgresql'
  is_builtin    INTEGER DEFAULT 0,
  conn_json     TEXT NOT NULL,          -- Fernet 加密的 JSON: {host,port,user,password,database,path}
  schema_json   TEXT,                   -- 内省 + 用户注释
  schema_updated_at TIMESTAMP,
  created_at    TIMESTAMP NOT NULL,
  updated_at    TIMESTAMP NOT NULL
);
CREATE INDEX idx_ds_user ON data_sources(user_id);

ALTER TABLE sessions ADD COLUMN datasource_id TEXT REFERENCES data_sources(id);
```

`schema_json` 结构：

```json
{
  "tables": [{
    "name": "orders",
    "comment": "订单主表",
    "columns": [
      {"name": "order_id", "type": "TEXT", "pk": true, "comment": "订单唯一 ID"},
      {"name": "customer_id", "type": "TEXT", "fk": "customers.customer_id", "comment": ""}
    ]
  }]
}
```

> v1 删掉了 `sample_values`：大表逐列采样成本不可控（olist geolocation 表几十万行），且 text2sql v1.5 未依赖样例值即达 96%。列入 §14 未来演进。

**内置 demo 的 schema_json 来源（关键）**：`builtin_olist`（`id='builtin_olist'`, `user_id='__builtin__'`）的 schema_json **不走自动内省**，由现有 `chatbi/schema.py` 人工精修版**离线转换导入**——保留全部业务注释、9 条外键关系、`customer_id` vs `customer_unique_id` 陷阱说明。96% 评测基线依赖这些人工信息；olist 链路的 prompt 保持 text2sql v1.5 原样。builtin 所有用户可读、不可改、不可删。

## 4. 后端 API

| Method | Path | 说明 |
|---|---|---|
| GET    | `/api/datasources`                  | 当前用户 + 全部 builtin |
| POST   | `/api/datasources/test`             | 试连接（不落库；先过 ssrf_guard，计入限流） |
| POST   | `/api/datasources`                  | 新建（ssrf_guard → 连 → 内省 → 存） |
| GET    | `/api/datasources/{id}`             | 详情（密码脱敏） |
| PATCH  | `/api/datasources/{id}`             | 改名 / 改注释 / 改连接（触发重连+重内省） |
| POST   | `/api/datasources/{id}/refresh_schema` | 手动刷新（合并保留用户注释，见 §9） |
| DELETE | `/api/datasources/{id}`             | 删除（builtin 拒绝；绑定 session 迁到 builtin_olist） |

归属校验规则：`user_id='__builtin__'` 的源对**所有用户可读**（特判，否则绑定 builtin 的会话会 403），不可改删；其余源严格校验 `user_id` 归属。

**绑定规则（写死）**：数据源为**会话级绑定**——创建会话时选择，会话内不可更换；切换数据源 = 新建会话。历史会话中的 artifacts 属于产生它的数据源，回放不受影响。

`POST /api/chat` 与 `/api/sessions` 增加可选 `datasource_id`：

- 无 session_id + 无 datasource_id → 走 `builtin_olist`（兼容策略 i）
- 新建 session 缺省 → 绑定 `builtin_olist`（兼容策略 iii）

## 5. 关键改造点

**`agent/tools/query_data.py`**：不再直连 `DB_PATH`（现 `query_data.py:29`），改为从 state 拿 `datasource_id`，通过 `sql_executor.execute(ds_id, sql)` 执行。`AgentState` 增加 `datasource_id` 字段；`stream_run()`/`run()` 入口接收并写入初始 state（现状两入口只有 question，见 `agent/graph.py:350-354, 405-409`）。

**prompt 三层拆分**（现 `prompts/text2sql.md` 把三类内容混在一个文件）：

| 层 | 内容 | 来源 |
|---|---|---|
| 通用层 | 安全规则 / 输出格式 / 重试纪律 | 所有数据源共享 |
| 方言层 | 日期函数 / LIMIT / 字符串拼接 / 布尔差异 | `chatbi/dialect.py` 的 cheatsheet 注入 |
| 业务层 | olist：`order_status='delivered'`、`category_translation` join、`customer_unique_id` 等 v1.5 片段**原样保留**；自建源：schema_json 用户注释经 `schema_render.py` 渲染 | 按数据源切换 |

`prompts/text2sql.md` 头部动态注入：

```
## 当前 SQL 方言：{dialect}
{dialect_cheatsheet}

## 当前数据库 Schema：
{rendered_schema_from_json}

## Few-shot 示例：
{few_shots_for_source}
```

**few-shot 选择规则**：builtin olist → `chatbi/few_shots/sqlite.py`（现有 10 组 olist 业务示例，与 96% 基线一致）；自建源 → 对应方言的 5–6 组**纯语法示例**（通用问法 + 通用表名），模板中显式标注"以下示例仅演示 {dialect} 语法，表名与当前数据库无关"，防止 LLM 照抄表名：

- `chatbi/few_shots/mysql.py`：日期分组 / GROUP BY / JOIN / 窗口函数
- `chatbi/few_shots/postgresql.py`：同上
- 自建 SQLite 源：通用 SQLite 语法示例（不含 olist 业务内容）

**planner 感知数据源**：`prompts/planner.md:12` 的 query_data 工具描述现写死"Olist 巴西电商数据集"，改为参数化 `{dataset_desc}`（builtin → 原描述；自建源 → 数据源 name + 用户注释摘要）。`agent/planner.py` 的 system 加载现无占位符机制（`planner.py:26-33` 模块级缓存），改为按数据源渲染（缓存键 = 数据源标识）。

**`chatbi/dialect.py`**（新）

- `get_dialect(ds_type)` → `"sqlite" | "mysql" | "postgresql"`
- `dialect_cheatsheet(dialect)` → 方言差异 markdown

**`services/sql_executor.py`**（新）

- **engine 缓存**：按连接串哈希做键的 LRU（上限 10，空闲 30 分钟 dispose）——替代现 `_get_engine` 的 `lru_cache(maxsize=1)` 单路径单例（`query_data.py:57-60`）；2C4G 内存约束
- **强制 LIMIT**：子查询包装 `SELECT * FROM (<原 SQL 去掉末尾分号>) AS _q LIMIT n`（对 CTE 结尾的语句安全，优于字符串追加）；n = `DATASOURCE_MAX_ROWS=500`，与 `_serialize_artifact` 的 `df.head(500)` 截断对齐
- **超时**：`connect_timeout=5s`；查询 30s（PG `statement_timeout` / MySQL `max_execution_time`）
- 执行前过 `chatbi/validator.py`（只允许 SELECT，保留现状）

## 6. 安全设计

公网开放"用户连接自己的云上数据库"意味着任何人可让服务器向任意 host:port 发起 TCP 连接（SSRF 跳板：内网探测、云元数据 169.254.169.254、端口扫描）。本期按以下四层缓解后开放：

1. **内网黑名单**（`services/ssrf_guard.py`）：连接前对 host 做 DNS 解析（`socket.getaddrinfo`），**用解析出的 IP** 校验（缓解 DNS rebinding），命中以下保留段一律拒绝：`10/8`、`172.16/12`、`192.168/16`、`127/8`、`169.254/16`、`0.0.0.0/8`、`::1`、`fc00::/7`、`fe80::/10`
2. **端口白名单**：默认仅允许 `3306`（MySQL）/ `5432`（PostgreSQL）；`DATASOURCE_ALLOWED_PORTS` 配置项可放宽（**严格默认 + 配置放宽**——已定稿）
3. **连接类接口限流**：`/api/datasources/test` 与 `POST /api/datasources` 计入独立限流桶，每 IP 每小时 `DATASOURCE_CONNECT_RATE_LIMIT=10` 次（复用按 IP 维度，与提问限流独立）
4. **残余风险显式声明**（写入 README/帮助文案）：自定义端口的云数据库默认连不上（需管理员配置放宽）；DNS rebinding 不能完全根除；前端表单强提示"**务必使用只读账号**"并附三大库创建只读账号 SQL 片段

其余安全措施：

- **密码加密**：Fernet 对称。`DATASOURCE_SECRET_KEY` **非必填**：未配置时自动生成随机 key 写入 `data/.datasource_key`（权限 0600）并复用，启动 warning 提示生产显式配置；builtin olist 不依赖该 key。（消除 v1"必填启动即报错"与"olist 行为完全不变"的矛盾）
- **SQL 校验**：保留 `chatbi/validator.py`，只允许 SELECT
- **强制 LIMIT**：见 §5 sql_executor
- **越权**：归属校验见 §4；`data/.datasource_key` 与 `sessions.db` 依赖 systemd `ReadWritePaths` 放行 `data/`（功能一 §12 已覆盖）

## 9. 错误处理

- 连接目标命中内网黑名单 → 400，提示"不允许连接内网/保留地址"
- 端口不在白名单 → 400，提示"仅允许 3306/5432 端口，如需其他端口请联系管理员配置 `DATASOURCE_ALLOWED_PORTS`"
- 试连接失败 → 400 带原始错误（脱敏凭证）
- 内省成功但表列表空 → 前端提示"未抓到表，请检查账号权限"
- **refresh_schema 合并策略**：重内省结果按 `table.column` 保留已有用户注释（注释合并，结构以新内省为准），不覆盖用户劳动
- 查询超时/权限不足 → 复用现有错误分类 UI
- 删除数据源时若有绑定 session → 迁到 `builtin_olist`（不删 session）
- 密码加解密异常 → 记 log 并拒绝该源的查询

## 10. 兼容策略

- `POST /api/chat` 无 session_id 无 datasource_id → 走 `builtin_olist`（i）
- 新建 session 缺省 → 绑定 `builtin_olist`（iii）
- **启动迁移**（功能一已上线 sessions.db 后执行）：`data_sources` 表 `CREATE TABLE IF NOT EXISTS`；`sessions.datasource_id` 列通过 `PRAGMA table_info(sessions)` 检查、缺失则 `ALTER TABLE ADD COLUMN`（SQLite 安全操作）
- olist 相关行为完全不变（同一份 few-shot + schema + v1.5 prompt），并以 §11 的基线回归验证
