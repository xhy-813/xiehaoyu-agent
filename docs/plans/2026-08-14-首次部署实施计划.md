## 实施步骤

### Step 0 控制台快照（用户手动，可选但建议）

控制台「快照」页为当前干净实例打一份手动快照，作为任何事故时的最终回滚点。

### Step 1 服务器基础准备（约 5 分钟）

```bash
# 1a. 2GB swap（npm build 内存峰值兜底，先 free -h 确认无现存 swap）
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# 1b. Node 20（deploy.sh 不装 Node，缺失会直接退出；走 npmmirror 二进制，gzip 格式避免依赖 xz）
curl -fsSL https://npmmirror.com/mirrors/node/v20.17.0/node-v20.17.0-linux-x64.tar.gz -o /tmp/node.tar.gz
sudo tar -xzf /tmp/node.tar.gz -C /usr/local --strip-components=1
node -v && npm -v
```

**验证**：`free -h` 见 2G swap；`node -v` 输出 v20.17.0。

### Step 2 克隆仓库 + 预置 .env（约 2 分钟）

先 clone 再跑 deploy.sh，使脚本走「更新」分支且 .env 已就位（避免脚本第 4 步退出、重复跑两遍）：

```bash
sudo git clone https://gitee.com/xiehaoyu12138/xiehaoyu-agent.git /srv/xiehaoyu-agent
sudo chown -R ubuntu:ubuntu /srv/xiehaoyu-agent
```

本地执行上传 .env（密钥不出现在命令与输出中）：

```bash
scp -i deploy/test.pem .env ubuntu@159.75.87.82:/srv/xiehaoyu-agent/.env
```

服务器上对齐非敏感项（**先 grep 再改，缺失则追加**，本地 .env 较简可能缺这些行）：

- `CORS_ORIGINS=http://159.75.87.82`
- `IP_HOURLY_QUOTA=40`、`GLOBAL_DAILY_QUOTA=500`（决策 3）
- 权限由 deploy.sh 统一收紧（root:www-data 640），此处无需处理

### Step 3 deploy.sh 主部署（约 5-10 分钟）

```bash
cd /srv/xiehaoyu-agent && sudo ./deploy/deploy.sh
```

不带域名参数 → `DOMAIN="_"`，跳过 certbot，纯 HTTP。脚本依次：apt 依赖 → git pull（ubuntu 身份）→ venv + requirements.lock（腾讯云内网 pip 镜像）→ .env 权限收紧 → npm install && build（ubuntu 身份，npmmirror）→ Nginx + systemd + 数据目录属主修正。

**验证**：`sudo systemctl status xiehaoyu-agent` active；`curl http://127.0.0.1:8000/api/health/ready` 返回正常（此时 RAG/ChatBI 数据未就位，后续步骤补齐）。

### Step 4 上传 olist.db（约 1-5 分钟，取决于家用上行带宽）

```bash
ssh -i deploy/test.pem ubuntu@159.75.87.82 'mkdir -p /srv/xiehaoyu-agent/chatbi/data'
scp -i deploy/test.pem chatbi/data/olist.db ubuntu@159.75.87.82:/srv/xiehaoyu-agent/chatbi/data/
```

服务以 `mode=ro` 只读打开，默认 644 权限即可，无需 chown。

### Step 5 构建 Chroma 向量库（约 1 分钟）

```bash
cd /srv/xiehaoyu-agent && sudo -u www-data .venv/bin/python -m rag.ingest --force
```

必须 `www-data` 身份（服务运行用户）；走智谱 embedding-3 API（.env 中 `EMBED_API_KEY`）。**验证**：输出 chunks 数应与本地一致（153）。

## 回滚方案

- 任一步骤失败：看 `journalctl -u xiehaoyu-agent` / 终端输出定位，修复后**重跑 deploy.sh**（脚本幂等，可重复执行）
- 系统性事故：控制台用 Step 0 快照回滚，或「重装系统」后从头执行本计划
- 数据事故：olist.db 本地有源文件可重传；向量库可随时 `--force` 重建

## 风险与对策

| 风险 | 对策 |
| --- | --- |
| npm build 内存不足（4GB + 2C） | 已加 2GB swap；仍失败则本地 `npm run build` 后 scp `frontend/dist/` 上传（备选路径） |
| pip 安装慢/个别包失败 | 腾讯云内网镜像免流量；重跑即可（已装包有缓存） |
| Gitee clone 异常 | 备选：本地 `git archive` 打包上传解压 |
| `EMBED_API_KEY` 失效导致 ingest 失败 | 检查智谱余额；兜底装 `requirements-embed-local.txt` 切本地 BGE |
| olist.db 上传慢（家用上行） | 107MB 约 1-5 分钟；中断用 `rsync --partial` 续传 |
| 文件属主混乱（root/ubuntu/www-data 三方） | 全程 ubuntu + sudo；deploy.sh 的 SUDO_USER 机制已处理（08-11 修复） |
| .env 缺配额/CORS 行导致 sed 落空 | 执行时先 grep，缺失则追加而非替换 |
