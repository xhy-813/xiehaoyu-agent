# 基于 K12 线上教育场景的 Hive 数仓分层与 PowerBI 可视化看板

## 关键信息
- 项目类型：数据仓库 / ETL / BI 可视化
- 时间：2026-06 ~ 2026-07
- 角色：独立完成（课程综合实训项目）
- 技术栈：Hive、HDFS、DataX、MySQL、PowerBI（DAX）、Java（UDF/UDTF）、Shell
- 数据规模：约 50 万条订单数据 + 9 科 1136 条课程维度标签

## 背景 (Situation)

某 K12 线上教育机构有一张约 50 万条的原始订单大宽表，字段杂、脏数据多，联报课程一单包含多个学科，业绩没法归属，业务方（管理层、九科业务、快递部门）拿不到能直接看的经营数据。学校课程实训要求我基于这份订单数据，从零搭一套完整的 Hive 数仓，并交付一套面向经营的 PowerBI 看板。

## 任务 (Task)

1. 完成从原始 CSV 到数仓分层（ODS → DWD → DWS → DIM）的完整 ETL 链路
2. 解决**联报课程业绩归属**这个业务核心难点
3. 对 Hive 作业做性能调优，让 9 科 ETL 能在合理时间跑完
4. 通过 DataX 把 DWS 层结果导出到 MySQL，对接 PowerBI
5. 搭建面向管理层、业务、快递三方的 PowerBI 经营看板
6. 用 Java UDF/UDTF 替换手工打标签的低效流程

## 行动 (Action)

### 1. 数仓四层分层设计

严格按照 **ODS → DWD → DWS → DIM** 的分层规范：

- **ODS 层**：`ods_total_orders` 外部表，TEXTFILE 存原始订单，不做任何清洗
- **DWD 层**：`dwd_total_orders` 做数据清洗，剔除奖励金、惩罚金、免费课程；渠道字段标准化；补齐 `dt_year`、`dt_month`、`dt` 三个日期衍生字段用于分区
- **DIM 层**：9 科课程维度表（语数英物化生政史地），共 1136 条课程标签，用 Excel 二维表快速打标后导入 Hive
- **DWS 层**：DWD LEFT JOIN 9 张维度表，UNION ALL 合成 `dws_total_orders` 总表；另单独出一张 `dws_total_package` 给快递部门做每日发货单

### 2. 联报课程业绩均摊逻辑

联报课程一单包含多个学科（比如"数学+物理+化学"打包课），直接算业绩会重复计算或归错科目。我的方案是：

- 通过维度表得到该课程涉及的学科数 `ref_subject_num`
- 每一科分摊金额 = `amount / ref_subject_num`
- 这样各科 GMV 加总等于总 GMV，业绩归属清晰

### 3. Hive 调优（4 种手段）

针对 9 科并行 ETL 慢的问题，逐个调优：

- **MapJoin**：小维度表广播到 Map 端，消除 Shuffle，Join 提速明显
- **分区裁剪**：按 `dt_year/dt_month/dt` 分区，查询扫描数据量减少约 91%
- **ORC + Snappy 压缩**：DWS 层改用 ORC 列存 + Snappy 压缩，存储占用减少约 75%
- **并行执行**：开启 `hive.exec.parallel`，9 科 ETL 并行跑，整体提速约 80%

### 4. Java UDF/UDTF 自定义函数

手工用 Excel 打 1136 条课程标签效率太低，我用 Java 写了两个函数：

- **GetSubject UDF**：输入课程名称，自动识别学科（正则 + 关键词匹配）
- **SplitCourseSubjects UDTF**：输入联报课程名，展开成多行学科明细

这两个函数集成后，理论上可以**跳过 9 张维度表**，一条 SQL 直接从 DWD 生成 DWS 总表，可复用到任何新增课程。

### 5. DataX 导出到 MySQL

写了 `hdfs_mysql.json` 配置，把 DWS 层的宽表从 HDFS 同步到 MySQL 的 `datax.dws_total_orders`，让 PowerBI 通过 MySQL 连接器读取。同时封装了参数化的 Shell 导入脚本，可以按日期增量跑。

### 6. PowerBI 6 页看板 + DAX 度量

对接 MySQL 后搭建 6 页看板：

- **总览页**：GMV、订单数、退款率、渠道占比 KPI
- **各科 GMV 页**：9 科横向对比
- **GMV 拆解页**：按时间、渠道、课程类型下钻
- **课程 & 渠道页**：课程类型 × 渠道交叉分析
- **科目分析页**：单科趋势、Top 课程
- **用户分析页**：地域分布（结合经纬度表）、复购

写了一批 **DAX 度量值**：累计 GMV（`CALCULATE + DATESYTD`）、退款率、渠道占比、课程类型占比等，让看板可交互切片。

## 结果 (Result)

- **数据规模**：完整跑通 **50 万条订单** + **9 科 1136 条** 课程维度标签的 ETL 全链路
- **业绩均摊**：联报课程业绩归属问题解决，各科 GMV 加总与总 GMV 误差 < 0.01%
- **性能提升**：分区裁剪减少 **91%** 扫描量，ORC+Snappy 减少 **75%** 存储，并行执行整体提速约 **80%**
- **打标签效率**：Java UDTF 替换手工 Excel 打标，1136 条课程标签从"手动分表打标"变成"一条 SQL 直出"
- **交付物**：6 页 PowerBI 经营看板 + 1 张快递每日发货单，覆盖管理层 / 业务 / 快递三方需求
- **文档**：产出完整项目文档 + Hive 调优与 UDF 集成指南，归档进个人知识库

## 面试话术

这个项目是我大三下学期做的一个课程综合实训，基于 K12 线上教育的 50 万条订单数据，从零搭了一套 **Hive 数仓 + PowerBI 看板**。

**背景**是原始数据是一张脏的订单大宽表，联报课程业绩没法归属，业务方也拿不到能直接看的经营数据。

我做了几个关键的事：

第一，**数仓分层**，严格按 ODS→DWD→DWS→DIM 四层来做。DWD 层做清洗，剔除奖励金、免费课程，补日期分区字段；DIM 层是我用 Excel 打的 9 科 1136 条课程标签；DWS 层做各科拆解。

第二，也是最有意思的，**联报课程业绩均摊**。一门"数学+物理"的打包课，直接算业绩会有归属问题。我的方案是按 `金额 / 涉及学科数` 均摊到各科，最终各科 GMV 加总和总 GMV 完全对得上。

第三，**Hive 调优**，我用了 4 种手段：MapJoin 消除 Shuffle、分区裁剪减少了 91% 的扫描、ORC+Snappy 压缩省了 75% 存储、并行执行让 9 科 ETL 整体提速 80%。

第四，我觉得最有成就感的是**写了两个 Java 函数**，一个 UDF 自动识别课程学科，一个 UDTF 展开联报课程。这样理论上可以跳过 9 张维度表，一条 SQL 就能从 DWD 直接生成 DWS 总表，未来加新课也不用重新打标。

最后通过 **DataX 把 DWS 导到 MySQL**，用 PowerBI 搭了 6 页看板，写了一批 DAX 度量值，包括累计 GMV、退款率、渠道占比这些，交付给管理层、九科业务和快递部门用。

这个项目让我完整走了一遍**数仓的分层规范、ETL 调优、UDF 扩展、BI 看板**的链路，对数据工程和数据分析之间怎么衔接体会很深。
