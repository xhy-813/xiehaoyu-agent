两条关键共性洞察：

1. **模拟面试是被多个同类项目验证过的强需求**，但竞品都把它做成独立入口、与主对话割裂——本项目把「面试官问 Agent」反转为「Agent 问候选人」，且复用同一套知识库与 SSE 架构，是差异化做法。
2. **引用来源展示是简历类 Agent 的信任关键**——本项目后端已产生 citations 数据但前端未渲染，等于自断一臂。

### T2【P0】联系方式口径放开（约 0.5 天）

现状矛盾：persona 要求「不直接报号码、引导到页脚」（`prompts/system_persona.md` 第 37 行），但页脚硬编码了邮箱和微信（`frontend/src/data/profile.ts` 第 37-38 行）——遮遮掩掩反而奇怪。决策：**放开**。

1. `system_persona.md` 联系方式规则改为：被问到时可直接告知邮箱与微信号，并可顺带提示页脚有入口。
2. 新增 `data/知识库/常见问题/13-联系方式.md`，含完整邮箱、微信、Gitee 地址。
3. `rag/ingest.py` 增加 PII 脱敏豁免白名单（如 `PII_EXEMPT = {"常见问题/13-联系方式.md"}`），该文件的 chunk 跳过 `_mask_pii()`；其余文件维持脱敏不变。新增单测覆盖豁免逻辑。
4. 聊天页转化出口（与 T4-7 合并实施）。
5. 验收：提问「怎么联系你」，Agent 直接给出邮箱/微信；其余知识库文件检索结果仍不脱敏手机号即视为回归失败。

### T3【P0】流式期间切换会话（约 0.5 天）

机制定位（已验证）：[SessionSidebar.vue](../../frontend/src/components/chat/SessionSidebar.vue) 第 22-27 行会话项无禁用样式（看着能点），点击后被 [chat.ts](../../frontend/src/stores/chat.ts) 第 224-226 行 `isStreaming` 守卫静默拦截——点击无效且无任何反馈。后端无此问题（SSE 的 session_id 发起时即确定）。

**采纳方案 A（切换即停止当前流）**，参考 CopilotKit 切换 thread 自动 abortRun 的做法：

1. `SessionSidebar.vue` 的 `onSelect`：`if (chat.isStreaming) { if (!confirm('当前正在生成回答，切换会话将中断本次回答，是否继续？')) return; chat.stopStreaming() }`，随后正常 `loadSession`。
2. 侧栏会话项在流式期间加 `title="生成回答中，点击切换将中断"` 提示（不加 disabled 样式，保持可点）。
3. 回归点：`stopStreaming()` 中断后原会话的部分回答落库行为不变（后端心跳检测断连后中止 LLM 调用，前端不做额外处理）。
4. 新增前端逻辑无单测设施，靠手动验证：流式中切换 → confirm → 停止 → 目标会话正常加载；取消 confirm → 留在原会话继续流式。

远期可选（本次不做）：每会话独立流状态（Map<sessionId, SessionState>，切换后旧会话后台继续流），约 200-300 行重构，秋招后再评估。

### T5【暂缓】模拟面试模式（设计保留，暂不实装；预估 2-3 天）

> 2026-08-09 用户决策：暂缓实施。以下设计保留，启用时可直接按此施工。

**定位**：把 Agent 从「被面试官提问」反转为「当面试官提问」，服务所有者自己的秋招刷题；对外的说服力在于「这个 Agent 的主人自己都在用它备战面试」。

**架构**（借鉴 DeepInterview 三阶段，简化为两阶段，复用现有 LangGraph/SSE/会话存储）：

1. **入口与流程**
   - `ChatView` 顶部加模式切换：「对话模式 / 模拟面试」；侧栏新建会话时可选模式（sessions 表加 `mode` 列，启动时 `PRAGMA table_info` 检查后 `ALTER TABLE` 补列，默认 `'chat'`）。
   - 开始：选方向（项目面 / 技术面 / 行为面 / 综合）+ 题数（默认 5）。
   - Live 阶段：逐题提问 → 用户作答 → 即时点评 → 下一题。每题最多 1 个追问，可跳过（跳过给提示）。
   - Post 阶段：全部完成后生成总结报告。
2. **出题**：MVP 不建独立题库——复用现有 RAG 知识库（12 篇 FAQ 即标准答案库 + 简历 + 项目文档），由 LLM 按所选方向基于检索到的候选人资料生成针对性问题（借鉴 Interview-Agent 的 resume-based 出题）。题库 YAML 化列为后续增强。
3. **点评结构**（借鉴 DeepInterview ScoreCard 四字段）：每题输出 JSON：`{strength, gap, model_answer, next_step, score(1-5)}`，前端渲染评分卡片（新组件 `ScoreCard.vue`，走现有 artifact 通道落库 `artifacts_json`，回放可见）。
4. **总结报告**：JSON rubric（完整性/准确性/表达/逻辑 各 1-5 分 + 强弱项 + 复习建议），**前端用现有 Plotly 渲染雷达图**（复用 `ChartRenderer`，零新依赖）。
5. **后端实现**：新增 `prompts/interviewer.md`；`POST /api/chat` 请求体加 `mode` 字段，`interview` 模式走轻量分支（单次 LLM 调用 + RAG 检索标准答案对比，**不经过 planner 四工具**，不侵入现有 graph.py）。面试进度（当前第几题、累计得分）由前端随请求回传，后端保持无状态；评分卡片与总结报告随消息落库。
6. **限流**：与对话共用 IP 小时配额即可，不单独开口。
7. **测试**：单测 mock LLM 返回评分 JSON（解析容错、追问上限、跳过分支、报告生成）；smoke 脚本真实跑完一轮 3 题面试。
8. **验收**：完整走完「选方向 → 5 题问答（含 1 次追问、1 次跳过）→ 总结报告雷达图」；刷新后回放评分卡片正常；301 条既有单测 + 新增用例全绿。
