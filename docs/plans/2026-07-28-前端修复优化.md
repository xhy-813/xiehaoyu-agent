## P0-1 `citations` 类型与后端不一致

### 现象与证据

前端类型声明（`src/utils/sse.ts:26`）：

```ts
citations?: Array<{ source: string; heading: string; score: number }>
```

后端实际产出（`agent/tools/introduce_me.py:66-74`）：

```python
citations = [
    {
        "source": h.source,
        "heading": h.heading,
        "distance": round(h.distance, 4),
        "similarity": h.similarity,
    }
    for h in hits
]
```

前端声明的 `score` 字段在后端**根本不存在**，后端产出的是 `distance` + `similarity`。这是 RAG 模块重构（commit `2848072`）后未同步更新前端类型导致的。

### 影响

目前 citations 未在前端渲染，所以无运行时错误。但类型声明是错误的"谎言"——后续若按 `score` 渲染引用列表，会静默拿到 `undefined`，排查成本高。

### 修复方案

修改 `src/utils/sse.ts:26`：

```ts
citations?: Array<{
  source: string
  heading: string
  distance: number    // cosine distance，越小越相关
  similarity: number  // 1 - distance，越大越相关
}>
```

### 验证

`vue-tsc -b` 通过即可。若后续要渲染引用列表（可作为 `introduce_me` 回答的可选增强），在 ChatMessage 内联结果区新增一个折叠区块读取 `dataArtifact.citations` 即可，数据链路已通。

## P1-4 消除 artifact 查找逻辑重复（含一处隐性不一致）

### 现象与证据

同一段"倒序遍历 trace 找最后一个含某字段的 artifact"逻辑写了两份：

- store 版（`src/stores/chat.ts:89-106`）：`dataArtifact` / `chartArtifact`，基于 `_activeTrace()`
- 组件版（`src/components/chat/ChatMessage.vue:152-165`）：`dataArtifact` / `chartJson`，基于 `props.message.trace`

且存在一处**取值规则不一致**：

- `chartTypeLabel`（store，`chat.ts:115-118`）：取**最后一个含 figure_json** 的 artifact 的 `chart_type`
- `chartTypeLabel`（ChatMessage，`ChatMessage.vue:178-181`）：`trace.find(...)` 取**第一个含 chart_type** 的步骤

当一次回答中有多次查询/可视化时，两者可能显示不同的图表类型标签。

### 修复方案

新建 `src/utils/artifact.ts`，提取共享查找函数（type-only 循环导入在 TS 编译期擦除，无运行时问题）：

```ts
import type { Artifact } from '@/utils/sse'
import type { ToolTrace } from '@/stores/chat'

/** 倒序查找 trace 中最后一个满足条件的 artifact（取最新一次结果） */
export function findLastArtifact(
  trace: ToolTrace[],
  predicate: (a: Artifact) => boolean,
): Artifact | null {
  for (let i = trace.length - 1; i >= 0; i--) {
    const a = trace[i].artifact
    if (a && predicate(a)) return a
  }
  return null
}

export const findDataArtifact = (t: ToolTrace[]) =>
  findLastArtifact(t, a => !!a.df_json)

export const findChartArtifact = (t: ToolTrace[]) =>
  findLastArtifact(t, a => !!a.figure_json)
```

然后：

- `chat.ts:89-106` 的两个 computed 改为调用 `findDataArtifact(_activeTrace())` / `findChartArtifact(_activeTrace())`
- `ChatMessage.vue:152-165` 改为 `findDataArtifact(trace.value)` / `findChartArtifact(trace.value)`
- **统一 `chartTypeLabel` 规则为"取最后一个图表 artifact 的 chart_type"**（与图表展示同源）：`ChatMessage.vue:178-181` 改为读 `chartArtifact?.chart_type`

### 验证

一次提问触发多次查询时（如"先看订单量，再看销售额"），消息的图表类型标签与所展示图表一致；其余渲染不变。

## P2-5 流式期间展示实时工具调用状态

### 现象与证据

后端 `stream_run()` 每次 planner 决策都会推送 `planner_decision` 事件（含 `next_action` / `next_tool` / `step`），前端 `sse.ts:87-89` 也已解析该事件并暴露 `onPlannerDecision` 回调——但 `chat.ts:160-179` 注册回调时只用了 `onToolEnd / onFinalAnswer / onError`，决策事件被丢弃。

结果：一次多步查询（最长 5 步，每步都是一次 LLM 调用 + 工具执行）期间，用户只能看到 spinner，无法感知 Agent 进行到哪一步。

### 修复方案

1. `chat.ts` 新增状态并在回调中维护：

```ts
const currentTool = ref<string | null>(null)  // 正在执行的工具名

// sendMessage 内：
onPlannerDecision: (data) => {
  currentTool.value = data.next_action === 'call' ? (data.next_tool ?? null) : null
},
onToolEnd: (data) => {
  currentTool.value = null
  // ...原有 push trace 逻辑
},
```

`finally` 中复位 `currentTool.value = null`；`clearChat()` 同步清理。store return 中导出。

2. 展示位置（二选一，推荐前者）：
   - **消息 loading 区**：`ChatMessage.vue:31-33` 的 `msg-loading` 中，spinner 旁显示 `正在调用「{{ toolLabel(chat.currentTool) }}」…`（复用 `tool-constants.ts` 的中文名映射）；
   - **输入框 hint 区**：`ChatInput.vue:32` 的 `input-hint` 在流式时显示当前步骤。

### 验证

提问一个需要多步的问题（如"查询销售额最高的品类并画图"），流式期间能看到工具名依次切换（数据查询 → 可视化 → 结果解读）。

## P2-6 增加流式停止按钮

### 现象与证据

中断能力其实已完整实现：

- `chat.ts:127-132` 每次发消息前 abort 旧流并新建 `AbortController`
- `chat.ts:181-183` catch 中已区分 `AbortError`，会把占位消息内容置为"请求已取消"

但 UI 上没有触发入口：`ChatInput.vue:17-29` 的发送按钮在流式时 `:disabled="!text.trim() || disabled"` 且 `:loading="disabled"`，用户只能干等（一次多步查询可能持续数十秒）。

### 修复方案

1. `chat.ts` 新增 action 并导出：

```ts
function stopStreaming() {
  abortController.value?.abort()
}
```

（abort 后走既有 `AbortError` 分支，内容置"请求已取消"，`finally` 复位状态，无需额外处理。）

2. `ChatInput.vue`：
   - 新增 prop `streaming: boolean`，新增 emit `stop`
   - 流式时发送按钮切换为**停止按钮**：图标改为方块（`M6 6h12v12H6z`），`type="error"` 或 `warning`，不 disabled，点击 emit `stop`；textarea 保持 disabled

```vue
<n-button
  v-if="streaming"
  type="error"
  circle
  @click="emit('stop')"
>
  <template #icon><n-icon size="18"><svg viewBox="0 0 24 24"><path fill="currentColor" d="M6 6h12v12H6z"/></svg></n-icon></template>
</n-button>
<n-button v-else type="primary" :disabled="!text.trim()" circle @click="handleSend"> ... </n-button>
```

3. `ChatMain.vue:18-21` 接线：`:streaming="chat.isStreaming" @stop="chat.stopStreaming"`。

### 验证

发送问题后立即点停止：流中断、消息显示"请求已取消"、动画状态经 error/idle 正常回落、可立即发送下一条。

## P3-7 （可选迭代）消息持久化

### 现象

`messages` 仅存内存 ref，刷新页面即丢失（README 后续迭代中已列"对话记忆持久化"）。

### 方案与取舍

直接整体持久化不可行：消息 trace 中含 `df_json` / `figure_json` 大字符串（单张图表可达数百 KB），sessionStorage/localStorage 配额约 5MB，几轮对话就会撑爆。

建议方案：

- 持久化时**剥离 artifact**：`trace` 保留 `{tool, args, summary}` 但 `artifact: null`（刷新后历史消息保留文本回答与执行轨迹摘要，图表/数据表不再展示）；
- 仅持久化最近 N 条（如 50 条）；
- 存 `sessionStorage`（与 token 生命周期一致，关标签页即清空，符合访问码场景的安全语义）；
- watch `messages` 变化时防抖写入，`clearChat()` 时同步清除。

若接受"刷新后历史图表消失"这一降级体验，可实现；否则建议维持现状，等后端会话持久化（真正的"对话记忆"）一起做。**本项不建议与上述 P0-P2 同批实施。**
