## 详细内容

### 项目背景
独立设计并实现一个基于 LLM Agent 的个人智能体与 ChatBI 系统，作为我的"数字分身"展示数据能力。

### 核心挑战

**挑战 1：多 Tool Agent 编排**
- 需要让 LLM 自主决策调用链（介绍本人 → 查数据 → 可视化 → 解读）
- 解决方案：基于 LangGraph 构建状态机，实现 planner → tool_router → tools → finalize 的循环执行
- 技术点：astream() 流式推送、状态管理、条件路由

**挑战 2：Text2SQL 准确率**
- 自然语言转 SQL 容易出错，特别是复杂多表查询
- 解决方案：完整 schema 描述 + 5 组 few-shot 示例 + sqlparse 语法校验 + 失败重试机制（最多 3 轮）
- 数据：Olist 电商数据集，9 张表关联，99,441 条订单

**挑战 3：SSE 流式推送**
- Agent 执行多步骤，用户等待时间长，需要实时反馈
- 解决方案：FastAPI SSE 流式推送，每个节点执行完立即 yield 事件到前端
- 配置：Nginx 需设置 proxy_buffering off

### 项目成果
- 完整功能：4 个 Tool（introduce_me/query_data/visualize/explain_result）
- 技术栈：Python / LangGraph / DeepSeek / ChromaDB / SQLite / Plotly / FastAPI / Vue 3 / Nginx
- 部署：腾讯云轻量服务器，JWT 鉴权 + 限流
- GitHub 开源，作为简历项目展示

## 面试话术

我做过最有挑战的项目是 Xiehaoyu-Agent，这是一个 LLM Agent 系统。

最大的挑战是**多 Tool 自主编排**。我需要让 LLM 自己决定什么时候查知识库、什么时候查数据库、什么时候画图。我用 LangGraph 做了状态机，实现了 planner → tools → finalize 的循环执行，最多支持 5 轮推理。

第二个挑战是**Text2SQL 准确率**。我用完整 schema + few-shot + 语法校验 + 失败重试四层保障，在 Olist 数据集（9 张表）上实现了较高的准确率。

第三个挑战是**SSE 流式推送**。Agent 执行需要几秒到十几秒，我用 FastAPI 的 SSE 让每个节点执行完立即推送到前端，用户体验接近 ChatGPT。

这个项目已经部署上线，作为我的"数字分身"可以回答关于我的问题和数据分析问题。
