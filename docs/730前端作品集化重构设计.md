# 前端作品集化重构设计文档

> 日期：2026-07-30 ｜ 状态：已确认 ｜ 实现路线：现有工程内重构

## 1. 背景与目标

Xiehaoyu-Agent 当前是一个"登录页 + 聊天页"的工具型前端。本次重构将其升级为**深色极客风单页作品集**，聊天作为页面其中一个区块嵌入。

**核心动机**：页面截图将放入简历/作品集（系列图），同时提升面试官现场打开链接时的第一印象。

**成功标准**：

- 每个区块在桌面/移动端截图都"能进简历"
- 面试官无需任何访问码即可体验完整聊天能力
- 聊天全流程（RAG 问答 / ChatBI 出图 / 执行轨迹 / 流式）在新页面中完整保留

### 4.2 字体

- 正文：`"PingFang SC", "Microsoft YaHei", "Segoe UI", sans-serif`
- 装饰/数字/编号：`ui-monospace, "JetBrains Mono", "Cascadia Code", Consolas, monospace`
- Hero 大字：`clamp(2.5rem, 6vw, 4.5rem)`，字重 800；次大字同尺寸、次要文本色
- 章节标题：`clamp(1.5rem, 3vw, 2rem)`，字重 700

### 4.3 动效

- 滚动入场：fade-up（IntersectionObserver，一次性触发，尊重 `prefers-reduced-motion`）
- Hero：页面加载入场序列（小字 → 大字 → 段落 → CTA 依次 fade-up）
- 导航：hover 时下划线/变色过渡
- 聊天内部现有动效全部保留（流光轨迹、流式光标、消息入场），配色适配深色
- 滚动行为：锚点跳转 `scroll-behavior: smooth`（reduced-motion 时关闭）

### 4.4 响应式

- 断点：`<768px` 移动端（复用现有 `useMediaQuery` composable）
- 移动端：侧边固定栏隐藏；导航变汉堡菜单（抽屉）；聊天区块内边距收窄
- 聊天窗口：桌面嵌入高 ~640px；移动端 ~70vh；全屏页（`/chat`）全端可用

### 5.2 聊天嵌入与全屏实现

- **嵌入模式**（`/` 聊天区块）：`ChatWidget` 渲染在卡片容器内（固定高度，内部滚动），头部含"全屏"按钮
- **全屏模式**（`/chat` 路由）：`ChatView` 重构为全屏页 —— 顶部返回栏 + 同一个 `ChatWidget` 组件铺满视口
- **状态保留**：消息列表、流式状态、AbortController 全部在 Pinia chat store（应用级单例），路由切换不丢消息、不中断 SSE，流式中切换全屏也安全
- **进入**：聊天区块全屏按钮 → `router.push('/chat')`
- **退出**：返回按钮或 ESC → `router.back()`（无历史时回退到 `/#chat` 锚点）

## 6. 后端改动（公开聊天）

| 改动 | 说明 |
|------|------|
| `/api/chat` 移除 JWT 依赖 | `dependencies.py` 鉴权依赖删除；chat router 不再校验 token |
| 限流按 IP 重构 | `rate_limit.py` 的 `check_rate_limit` 从 JWT user_id 改为客户端 IP；配额新增配置 `ip_hourly_quota`（默认 20 次/小时/IP） |
| 新增全局日上限 | `global_daily_quota`（默认 200 次/天，全站合计）；超限返回 429 + 友好文案"今日体验名额已用完，欢迎明天再来，或通过页脚联系方式找我" |
| 真实 IP 获取 | 读取 `X-Forwarded-For` 首跳（uvicorn `--proxy-headers` / 受信代理）；部署文档补充 Nginx `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;` |
| 删除登录体系 | `routers/auth.py`、`schemas/auth.py`、JWT 相关 settings（`jwt_secret`、`access_code` 等）、`rate_limit.py` 中的 `check_login_rate_limit` 一并删除 |
| CORS / SSE | 不变（生产同源，Nginx 已配 `proxy_buffering off`） |

**范围外**：Redis 限流。单进程内存限流对 2C4G 单机部署够用；在代码注释与文档中注明"重启清零、多 worker 不共享"的限制。

## 8. 错误处理与边界

| 场景 | 处理 |
|------|------|
| 429 IP 小时限流 | 聊天区内联提示"本小时提问次数已达上限，约 X 分钟后重置"（沿用现有文案风格），不弹窗不重定向 |
| 429 全局日上限 | 内联提示"今日体验名额已用完……" |
| SSE 断线/错误 | 保留现有"执行失败 + 重试按钮"逻辑 |
| 全屏页 ESC / 返回按钮 | `router.back()` 回到作品集聊天区块，消息状态保留 |
| 流媒体式中切换路由 | 允许；流状态在 Pinia store，路由切换不中断 |
| 无 JS / SEO | `index.html` 更新 title/描述 meta；语义化 HTML 标签（header/main/section/footer/nav） |

## 9. 性能与无障碍

- Plotly 保持按需动态加载（仅出现图表时）；Lottie 按状态懒加载保持
- 首屏（Hero）零重型依赖：无 Plotly、无 Lottie（头像不在主页）、无 Naive UI 组件渲染需求（作品集区块纯 CSS）
- `prefers-reduced-motion`：全站动效降级（含 reveal、smooth scroll、Lottie 现有逻辑）
- 文本对比度：`#ccd6f6`/`#8892b0` 对 `#0a192f` 背景均过 AA
- 焦点环使用薄荷绿，键盘可达（导航、chips、全屏按钮、ESC）
