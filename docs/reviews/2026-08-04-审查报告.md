### 2.2 数据流

```
用户输入 question
  → ChatRequest (Pydantic: min_length=1, max_length=10000)
  → Rate Limiter 检查 (IP 每小时 + 全局每日)
  → LangGraph stream_run()
    → planner_node: LLM 决策 {action, tool, args}
    → tool_node: 执行具体工具 (RAG/Text2SQL/Viz/Explain)
    → 循环 ≤ 5 步
    → finalize_node: 生成最终回答
  → SSE 流式推送 yield 事件:
    - planner_decision: LLM 决策信息
    - tool_end: 工具执行结果 (含序列化的 DataFrame/Plotly Figure JSON)
    - final_answer: 最终回答
    - data: [DONE] 结束
  → 前端渲染 Markdown + Plotly 图表 + Naive UI 数据表
```

- 请求验证顺序正确：先检查 IP 限流 → 再检查全局上限，避免被拒请求消耗全局配额

### 3.3 Agent 系统 (`agent/`)

**设计**：LangGraph 状态机，planner → tool_router → tools → planner 循环，最多 5 步。工具注册表是单一事实来源，自动派生工具名称列表。

**✅ 优点：**

- LangGraph 状态机设计清晰，`AgentState` TypedDict 定义完整
- 工具注册表 `TOOLS` dict 是单一事实来源，`_TOOL_NAMES` 自动派生，避免不一致
- `_make_tool_node()` 工厂函数避免重复代码
- 未知工具名安全降级到 `finalize` 而非崩溃（`router()` 函数）
- Planner JSON 解析使用大括号计数而非正则，正确处理嵌套 JSON（如 `"answer": "使用 Pandas (Python 库)"`）
- 所有节点异常都被捕获，`planner_node` 失败时自动降级到 `finalize`，不会导致整个状态机崩溃
- `_run_tool()` 区分预期错误（`APIError`, `ValueError`, `RuntimeError`）和编程错误（`TypeError`, `NameError`），后者正常传播
- 流式入口 `stream_run()` 使用 LangGraph 的 `astream()` 原生异步流式，事件类型清晰

**⚠️ 问题：**

| # | 严重度 | 问题 | 文件:行号 |
|---|---|---|---|
| A1 | 中 | **Planner 未对用户输入做注入防护** — 用户问题直接拼入 planner 的 LLM prompt：`f"【用户问题】\n{question}\n\n【已执行步骤】\n{trace_text}"`。虽然 `introduce_me` 工具有注入检测（`_sanitize_input`），但 planner 是第一个处理用户输入的节点，恶意 prompt 可在 planner 阶段就影响决策（如诱导调用错误工具、跳过限制） | [agent/planner.py:81-84](../../agent/planner.py#L81-L84 |
| A2 | 低 | **Planner system prompt 缓存在全局变量** — `_PLANNER_SYSTEM` 在模块首次加载后不再更新，无法热更新 prompt。虽为性能优化，但缺少文档说明 | [agent/planner.py:22-28](../../agent/planner.py#L22-L28 |

**prompt 注入防护现状（`introduce_me` 工具）：**

`introduce_me.py` 中的 `_sanitize_input()` 实现了 6 种注入模式检测：

1. `ignore (all)? (previous|prior|above|the above) (instructions?|rules?|constraints?)` — 忽略指令
2. `(system|assistant|user): $` — 角色切换标记
3. `you are now (a )?(different|new|another) (assistant|ai|bot|agent)` — 身份篡改
4. `forget (everything|all) (you know|you've (learned|been told))` — 记忆擦除
5. `\[system\]\s*\(` — 系统指令标记
6. `<\|im_start\|>|<\|im_end\|>` — ChatML 特殊标记

此外还剥离了 Markdown 代码块（防止用代码块包裹注入内容）。**但此防护仅在 `introduce_me` 工具中生效，planner 和其他工具未覆盖。**

### 3.5 ChatBI 模块 (`chatbi/`)

**设计**：Text2SQL 通过 LLM 生成 SQL → 多层安全校验 → 参数化执行 → 失败重试。Olist 巴西电商数据集（9 张表，~10 万条订单）。

**✅ 优点：**

- **SQL 安全校验多层次**（`validator.py`）：
  1. 清理 Markdown 代码块和末尾分号
  2. 剥离 SQL 注释（行注释 `--` 和块注释 `/* */`）
  3. 检查单语句（`sqlparse.parse()` 必须恰好返回 1 条语句）
  4. 检查语句类型：SELECT 直接通过，UNKNOWN 检查是否为 CTE（WITH...SELECT）
  5. 检查语句首关键字为 SELECT 或 WITH
  6. 剥离字符串字面量后检查禁止关键字黑名单
- 禁止关键字列表覆盖全面：`INSERT/UPDATE/DELETE/DROP/ALTER/CREATE/TRUNCATE/REPLACE/ATTACH/DETACH/PRAGMA/VACUUM/REINDEX/GRANT/REVOKE/EXPLAIN`
- 正确处理 CTE（`WITH...SELECT`）被 sqlparse 报告为 UNKNOWN 类型的边界情况
- 字符串字面量剥离（`_STRING_LITERAL_RE`）避免 `SELECT 'INSERT' AS action_type` 被误判为包含 INSERT
- SQL 执行使用 SQLAlchemy 参数化查询（`pd.read_sql(text(sql), conn)`），防止 SQL 注入
- 最多重试 `SQL_RETRY_MAX`（默认 3）次，指数退避（500ms → 1s → 2s，上限 5s）
- 每次重试将上一次的错误信息作为 feedback 传给 LLM，提高修正成功率
- Few-shot 示例覆盖时间过滤、聚合、排序 Top-N、JOIN、分类翻译 5 种典型场景

**⚠️ 问题：**

| # | 严重度 | 问题 | 文件:行号 |
|---|---|---|---|
| C1 | 低 | `_STRING_LITERAL_RE` 正则 `r"'[^']*'"` 无法处理 SQL 中 `''` 转义的单引号（如 `SELECT 'it''s fine'`），可能导致字符串被错误剥离后关键字检查失效。但由 LLM 生成的 SQL 几乎不会出现此场景 | [chatbi/validator.py:35](../../chatbi/validator.py#L35 |

### 3.6 前端 (`frontend/`)

**设计**：Vue 3 + TypeScript + Vite + Naive UI。深浅色主题通过 CSS 变量驱动，SSE 实时接收 Agent 事件，Plotly 渲染图表，Lottie 动画。

**✅ 优点：**

- **XSS 防护到位**：
  - `markdown-it` 配置 `html: false` 禁用 HTML 标签，`<script>` 会被转义为 `&lt;script&gt;`
  - 链接渲染器只允许 `http://` 和 `https://` 协议，阻止 `javascript:` 和 `data:` URI
  - 被阻止的链接设置为空 href 并显示 `[blocked: ...]` 提示
- 深浅色主题通过 CSS 变量驱动，`useTheme()` composable 全局单例同步到 `<html data-theme>`
- SSE 客户端具备完整错误处理：超时（120s）、重试（最多 3 次，指数退避）、AbortController 支持
- Plotly 使用 `plotly.js-dist` 按需动态 import（`ensurePlotly()`），减小首屏体积
- Lottie 动画也按状态懒加载，`loadToken` 竞态守卫防止快速切换时过期动画覆盖新动画
- 支持 `prefers-reduced-motion` 无障碍偏好：动画仅显示静态首帧
- 移动端响应式优化：双列布局 → 单列，`SectionHeading` 移动端自动恢复可见
- `ChatMessage` 组件交互完整：复制、重试、执行轨迹时间线、数据表、图表渲染

**⚠️ 问题：**
